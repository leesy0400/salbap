# 살림밥상 코드 구조

예전에는 `index.html` 한 파일(2,674줄, 1.4MB)에 디자인·로직·데이터가 다 들어 있었어요.
지금은 **역할별로 42개 파일**로 나눴고, 화면과 기능은 예전과 똑같아요.
(바꾼 직후 예전 코드와 새 코드로 화면 30개를 똑같은 상태로 그려 비교했고, 화면 HTML이 모두 같았어요.)

언어는 그대로 **HTML·CSS·순수 JavaScript**예요. 빌드 과정이 없어서 GitHub main에 올리면 Vercel이 지금처럼 바로 배포해요.

```
index.html          껍데기 — 글꼴, CSS 4개, 스크립트 37개를 순서대로 불러요
css/                화면 디자인
data/               ★ 건드리면 안 되는 데이터 (가격·동 목록·알레르기·거르는 말 …)
js/core/            바탕 — 설정, 저장, 로그인, 날짜·예산 계산, AI 부르기
js/logic/           기능 — 냉장고, 장보기, 메뉴 조합, 레시피, 밥풀이 계산
js/screens/         화면 그리기 — 온보딩, 홈, 장보기, 냉장고, 레시피, 기록, 내 정보
js/app.js           시작점 — 지금 화면을 그리고, 뒤로 가기를 관리해요
api/                서버 함수 (Vercel) — AI 호출, 메뉴 그림. API 키는 여기서만 써요
img/                밥풀이·첫 화면 그림
privacy.html        개인정보 처리방침
tests/              자동 검사 (npm test)
```

## 꼭 지킬 규칙: 불러오는 순서

모든 파일이 이름을 함께 쓰는 방식이에요(예: `render()`는 어느 파일에서나 불러요).
그래서 **`index.html`의 `<script>` 순서가 중요해요**: `data → js/core → js/logic → js/screens → js/app.js`.
새 파일을 만들면 같은 폴더 줄 사이에 넣고, `js/app.js`는 항상 맨 마지막에 둬요.
`npm test`가 이 순서와 빠진 파일, 같은 이름 두 번 만들기를 검사해요.

## data/ — 건드리면 안 되는 데이터

출처가 정해진 표이거나 팀이 직접 검증한 값이에요. 고칠 일이 있으면 팀과 먼저 상의해 주세요.

| 파일 | 들어 있는 것 | 출처·근거 |
|---|---|---|
| `prices.js` | **실제 가격 데이터** — 서울 25개 구 가게 131곳, 가게별 품목 가격·규격·조사일 | 팀이 모은 `shopping_db.json` 그대로 (1.1MB) |
| `foods.js` | 식재료 품목표 74개 — 품목코드별 이름·분류·이모지·다른 이름·기피 키워드 | 가격 데이터 품목코드 기준 |
| `dongs.js` | 서울 행정동 427개 → 법정동 목록 | 서울시 「자치구별 동 현황」(2025-08) |
| `allergy.js` | 알레르기 22종 단어, 팀 정답표(조미료 단어·품목코드 → 성분) | 식약처 표시 대상 + 팀 검증표(2026-11-10) |
| `filters.js` | 건강·안전 요청 단어(AI 안 부르고 안내), 메모 금칙어(욕설·정치·성적·마약 등) | 팀 결정 |
| `words.js` | 직접 입력 사전 — 식재료·조미료 이름으로 받아 주는 단어 | 팀 결정 (막히는 재료는 여기 추가) |
| `menu-words.js` | '먹고 싶은 메뉴' 판별 — 메뉴 끝말(찌개·볶음…), 메뉴 이름, 막는 말(위주·빼고…) | 팀 결정 |
| `seasonings.js` | 조미료 묶음(기본·장류…)과 기본 체크 4개, '목록에 없던 것도 샀어요' 종류 | 팀 결정 |
| `budget-refs.js` | 예산 버튼(10·20·30만 원), 가구별 평균 식비·외식비, 배달 한 끼 14,000원 | 가계동향조사, 소비자공익네트워크 조사 |

### 가격 데이터는 어디에 있나요?

- **지금:** `data/prices.js` 파일 하나예요. 서버나 Firebase DB가 아니라 **앱 파일과 함께 Vercel에 올라가는 정적 파일**이에요. 앱을 열면 휴대폰이 이 파일을 받아서 써요.
- **예전:** `index.html` 716번째 줄 `<script id="shopdb">` 안에 같은 JSON이 통째로 들어 있었어요.
- **새 데이터로 바꿀 때:** `data/prices.js`에서 `window.SHOP_DB = ` 뒤의 JSON만 새 `shopping_db.json` 내용으로 바꾸고, 맨 끝 `;`는 남겨요. `npm test`가 형식을 확인해 줘요.
- 사용자 기록(냉장고·장보기·레시피)은 다른 곳이에요: 휴대폰 브라우저(localStorage) + 로그인하면 Firebase Firestore `users/{uid}` 문서.

## js/app.js — 시작점

`render()`가 지금 상태(`S`, `DB`)에 맞는 화면 하나를 골라 그려요. 화면이 바뀔 때마다 브라우저 기록에 남겨서
휴대폰 뒤로 가기와 화면 위 ← 버튼이 바로 전 화면으로 돌아가게 해요(`navSync()`, `flowBack()`).
파일 맨 끝에서 첫 화면을 그리고 로그인을 시작해요.

## 보안 — 키는 어디에

| 값 | 위치 | 공개돼도 되나 |
|---|---|---|
| Claude API 키 | Vercel 환경변수 `ANTHROPIC_API_KEY` (서버 `api/llm.js`만 씀) | 안 됨 |
| Gemini API 키 | Vercel 환경변수 `GEMINI_API_KEY` (서버 `api/image.js`만 씀) | 안 됨 |
| Firebase 웹 설정(apiKey AIza…) | `js/core/config.js` | 됨 (원래 공개용. 보호는 `firestore.rules`가 담당) |
| 사용자 비밀번호 | Firebase Auth | 우리 코드·DB에 없음 |

`npm test`가 화면 코드에 Claude 키 모양 글자나 서버 키 값이 들어가면 실패하게 해 뒀어요.

## 자주 고치는 곳 빠른 안내

| 하고 싶은 것 | 고칠 곳 |
|---|---|
| 전체 색 바꾸기 | `css/base.css` 맨 위 `:root` |
| 문구 하나 바꾸기 | 그 화면의 `js/screens/*.js`에서 글자를 검색 |
| 밥풀이 그림 위치·말풍선 | `js/logic/bapuri.js`의 `SCENE` |
| AI 모델 바꾸기 | `js/core/config.js`의 `LLM` |
| 막히는 재료 이름 풀기 | `data/words.js`에 단어 추가 |
| 금칙어 추가 | `data/filters.js`의 `BAN_WORDS` |
| 가격 데이터 새로 넣기 | `data/prices.js` (위 '가격 데이터는 어디에' 참고) |

## 코드 모양 맞추기

`js/`와 `css/`는 Prettier로 줄을 맞춰 뒀어요(`.prettierrc.json`). `data/`는 표 모양을 그대로 두려고 제외했어요.
고친 뒤 모양을 맞추려면: `npx prettier@3.3.3 --write "js/**/*.js" "css/*.css"`
